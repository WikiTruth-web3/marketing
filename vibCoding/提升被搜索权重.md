# 如何进一步提升网站被搜索与抓取的权重

本文面向本仓库营销站（Vite + SPA、`index.html` 已含基础 meta、OG、JSON-LD）的后续优化清单，兼顾**搜索引擎**与**可被 AI/聚合服务引用**的发现能力。

---

## 一、当前基础（保持并迭代）

- 英文为主的 `title` / `description` / `canonical`。
- Open Graph、`twitter:card`、多 `og:locale:alternate`。
- JSON-LD（`WebSite`、`SoftwareApplication`）与 `inLanguage`、多语言 `keywords`。

后续应随产品文案**定期微调**标题与描述，避免全年不变；重要页面可单独写 `title`/`description`（见路由级 SEO）。

---

## 二、技术侧：抓取与索引质量

### 1. SPA 与首屏 HTML

爬虫会执行 JavaScript，但**首屏依赖过多 JS**会拖慢「可索引内容」出现时间。

- **预渲染（Prerender）**：对首页、`/technology`、`/blogs` 等关键路径生成静态 HTML（如 `vite-plugin-ssr`、托管方提供的 prerender、或构建时渲染）。
- **或 SSR**：若长期投入 SEO，服务端输出首屏 HTML 更稳。

目标：在不执行或少执行 JS 时，HTML 里已有**清晰的 H1、段落、站内链接**。

### 2. `robots.txt` 与 `sitemap.xml`

- **`robots.txt`**：允许抓取主要路径；勿误封 `/` 或整站；指向 sitemap 地址。
- **`sitemap.xml`**：列出重要 URL、`lastmod`、必要时 `hreflang` 与多语言 URL（见下文）。提交到 **Google Search Console**、**Bing Webmaster Tools**。

### 3. 性能与体验（间接影响排名）

- **Core Web Vitals**：LCP、INP、CLS；压缩图片、合理分包、字体与关键 CSS。
- **移动端可用性**：视口、可点击区域、勿用无法抓取的纯画布替代正文。
- **HTTPS**、**HTTP 状态码**正确（301 合并重复域名到 canonical 主机名）。

### 4. 结构化数据（在「页面可见内容」一致的前提下扩展）

- 博客/文章页：使用 **`Article` / `BlogPosting`**（作者、`datePublished`、`image`）。
- 有常见问题区块：**`FAQPage`** 必须与页面上可见问答**逐条对应**。
- 组织信息：**`Organization`**（`sameAs` 指向 X、GitHub、Telegram、文档站等）。
- 用 [Rich Results Test](https://search.google.com/test/rich-results) 校验无报错。

### 5. 多语言与 `hreflang`

- 当存在**真实可访问**的各语言 URL（如 `/zh/`、`/de/` 或子域）时，为每页配置 **`link rel="alternate" hreflang="..."`** 与 **`x-default`**。
- 仅有单 URL 时，不宜把所有 `hreflang` 指向同一地址；当前用 `og:locale:alternate` + JSON-LD `inLanguage` 是合理过渡。

## 三、内容与信息架构

### 1. 意图覆盖与长尾

- 按用户问题写内容：**匿名举报流程、隐私边界、奖励/经济模型、与司法或合规的关系**等；每篇一个主意图，避免堆砌关键词。
- 标题层级：**一页一个 H1**，H2/H3 反映小节，便于摘录与 AI 分段理解。

### 2. E-E-A-T（经验、专业、权威、可信）

举报/证据类主题对**可信度**敏感。

- 团队、审计、合作伙伴、文档与开源仓库等**可验证外链**。
- 法律免责声明、风险说明、用户责任：**清晰、诚实**，避免夸大承诺。
- 更新日期、版本说明（产品/白皮书变更时同步页面）。

### 3. 内链

- 从首页到技术页、博客、文档、应用入口的**文字链接**充足；避免重要页面只有按钮无 `<a href>`。

---

## 四、站外与品牌信号

- **高质量外链**：媒体报道、研究引用、生态伙伴页面；避免购买垃圾链接。
- **一致的品牌实体**：维基式名称在 X、GitHub、文档、应用域名间统一，便于知识图谱聚合。
- **Search Console / Bing**：监控抓取错误、索引覆盖率、查询词，据此改标题与内容。

---

## 五、面向「AI 与聚合发现」的补充做法

说明：各模型训练与检索策略不同，以下**不保证**单独带来排名，但普遍有利于**可被引用、可摘要、少幻觉**。

- **页面上事实明确**：产品名、链名（如 Oasis Sapphire）、机制名称（如 Truth Box、延迟披露）与**一句定义**，减少二次解读偏差。
- **`llms.txt`**（可选）：在站点根路径提供面向 LLM 的简短索引与政策说明（若采用，需与真实内容一致，避免「仅给机器看」的误导性文案）。
- **开放图谱图**：补充 **`og:image`**（建议约 1200×630），提升分享卡片质量，间接增加曝光与外链。

---

## 六、可执行的优先级建议

| 优先级 | 动作 |
|--------|------|
| 高 | 提交 sitemap；Search Console / Bing 验证；关键路由预渲染或 SSR |
| 高 | 博客/文档内链到首页核心概念；Organization + Article 结构化数据 |
| 中 | 各语言独立 URL + hreflang；每页独立 title/description |
| 中 | Core Web Vitals 与 LCP 优化；`og:image` |
| 持续 | 内容按查询意图迭代；监控索引与点击率再改 meta |

---

## 七、合规与敏感领域提醒

涉及举报、证据与激励时，注意各司法辖区宣传与金融表述边界；SEO 文案应与**产品实际能力**一致，避免为流量做不实表述，以免损害品牌与索引信任。
